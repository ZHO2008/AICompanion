# 打包与分发

> 目标读者：要给别人出一个能跑的 AICompanion 包的人。
> 本文回答两件事：**怎么打**、**打出来的包在干净机器上到底还需要什么**。

相关文件：

- [`tools/pack-release.ps1`](../tools/pack-release.ps1) —— 本文主推的可复现发布脚本（自带完整性断言）
- [`tools/pack.ps1`](../tools/pack.ps1) —— 旧的"全家桶 + Inno Setup 安装包"脚本
- [`tools/verify_dist.ps1`](../tools/verify_dist.ps1) —— 分发包异目录启动验证
- [`installer/AICompanion.iss`](../installer/AICompanion.iss) —— Inno Setup 6 安装脚本

## 0. 先说结论：以前的包缺什么

用户反馈"之前打包好像没带环境"，调查后确认**确有其事，而且不止一处**。逐条列证据。

### 0.1 `modules\` 根本没被打进包（最严重）

`llama-server.exe` 与 `ggml*.dll` / `llama*.dll` 现在住在 `modules\llm-cuda\` 和
`modules\llm-vulkan\` 里，程序按 `Path.Combine(AppPaths.Root, "modules")` 扫描
`module.json` 来发现后端（见 `src/AICompanion.App/SettingsWindow.xaml.cs` 里的
`ModulesPathText`、`ModuleRegistry.Scan`）。

而 `tools/pack.ps1` 从头到尾**没有任何一行**处理 `modules\`：

```
PS> Select-String -Path tools\pack.ps1 -Pattern 'modules' -SimpleMatch
tools\pack.ps1:229    '- 语音合成：Piper → 系统 SAPI'          # 只是说明文本
tools\pack.ps1:310    '  models\piper\zh_CN\*.onnx ...'        # 只是说明文本
```

结果：分发包里没有 `modules\`，程序扫不到任何后端，**对话功能在别人机器上等于没有**。
已发布的 `dist\AICompanion-0.9.2-win-x64\` 可以直接印证：该目录下没有 `modules\`。

### 0.2 `bin\` 的布局变了，打包脚本没跟上

同一份 `pack.ps1` 仍然只做 `Get-ChildItem 'bin' -File | Copy-Item ...`（只拷顶层文件）。
可仓库根目录 `bin\` 现在只剩：

```
ai_asr.dll  libfvad.dll  llama-batched-bench-impl.dll  llama-bench-impl.dll
llama-cli-impl.dll  llama-completion-impl.dll  llama-fit-params-impl.dll
llama-perplexity-impl.dll  llama-quantize-impl.dll  （外加 cpu-backup\ 子目录）
```

**没有 `llama-server.exe`、没有 `ggml*.dll`、没有 `llama*.dll`、没有 `mtmd.dll`。**
这些已经搬去 `modules\`。于是按现在的仓库重打一次包，`bin\` 里只剩一堆
`llama-*-impl.dll`——它们是 `llama-server.exe` 的伴生插件，**没有 exe 就是死文件**。

对比 `dist\AICompanion-0.9.2-win-x64\bin\`（0.9.2 时代打的包）：那里有完整的
`llama-server.exe` + `ggml*.dll` + `llama*.dll` + `mtmd.dll` + CUDA 运行库。
也就是说：**以前的包能跑，现在按同样命令重打反而会坏**。

顺带一提，`tools/verify_dist.ps1` 的必需文件清单里还写着 `bin\llama-server.exe`，
拿它验证现在的 `pack.ps1` 产物会直接 `throw`——守卫脚本比打包脚本更早发现了这个问题。

### 0.3 原生库动态依赖 MSVC 运行库，但从未随包

`README.md` §10.3 写着"Visual C++ 运行库：不需要（静态链接）"。
实测读导入表（在二进制里找 `MSVCP140.dll` / `VCRUNTIME140.dll` 字符串）：

| 二进制 | MSVCP140 | VCRUNTIME140 | VCRUNTIME140_1 | 其它 |
| --- | --- | --- | --- | --- |
| `bin\ai_asr.dll` | ✅ | ✅ | ✅ | `api-ms-win-crt-*`（UCRT） |
| `bin\libfvad.dll` | — | ✅ | — | UCRT |
| `modules\llm-cuda\llama-server.exe` | — | ✅ | — | UCRT |
| `modules\llm-cuda\llama.dll` | ✅ | ✅ | ✅ | UCRT |
| `modules\llm-cuda\ggml-cuda.dll` | ✅ | ✅ | ✅ | `cublas64_13.dll` |
| `modules\llm-vulkan\ggml-vulkan.dll` | ✅ | ✅ | ✅ | `vulkan-1.dll` |
| `Live2DCubismCore.dll` | — | — | — | 只依赖 KERNEL32 |

**结论：不是静态链接。** Windows 只自带 UCRT（`api-ms-win-crt-*`），
`MSVCP140.dll` / `VCRUNTIME140.dll` 来自 **VC++ 2015-2022 可再发行包**，
系统不预装。干净机器上缺它们时的症状极具迷惑性：

- 主窗口正常弹出（托管代码不需要它们）；
- `ai_asr.dll` 用 `NativeLibrary.Load` 加载失败 → ASR 静默降级；
- `llama-server.exe` 起不来 → 对话静默降级/报错。

开发机上一切正常，只是因为本机装过 VC++ 可再发行包 / Visual Studio。

### 0.4 CUDA 后端缺 `cublas64_13.dll`

`ggml-cuda.dll` 依赖 `cublas64_13.dll`，而它**不在** `modules\llm-cuda\` 里
（旧的 `pack.ps1` 是把 CUDA 运行库拷进 `bin\` 的，模块化之后这条逻辑失效）。
没有 CUDA Toolkit 的机器上，`llm-cuda` 模块起不来，只能退回 `llm-vulkan` 或 CPU。

### 0.5 `Live2DCubismCore.dll` 被旧脚本主动剔除

`pack.ps1` 默认（`-IncludeLicensedAssets` 关闭）会把这个 DLL 从产物里删掉，理由正当：
它归 Live2D 公司授权。但用户视角就是"没带环境"——形象只剩降级色块。
`pack-release.ps1` 默认**带上**它（因为断言要求），**公开分发前请自行确认 Live2D 授权**。

### 0.6 其它零碎

- `dist\AICompanion-0.9.2-win-x64\logs\app\app-20261029.log` —— 开发机的运行日志被打进了分发目录。
- `pack.ps1` 默认 `-IncludeModels $true`，产物 1.6 GB 起，不便回归比对。
- `Compress-Archive`（Windows PowerShell 5.1）写出的 zip 条目名用**反斜杠**，
  不符合 ZIP 规范；非 Windows 解压工具会把 `bin\ai_asr.dll` 当成一个文件名。

### 0.7 当前构建产物是"框架依赖"，不是自包含

`src\AICompanion.App\AICompanion.App.csproj` 的事实（逐项确认）：

| 属性 | 值 | 说明 |
| --- | --- | --- |
| `TargetFramework` | `net8.0-windows` | |
| `SelfContained` | **未设置** | 由命令行决定，默认框架依赖 |
| `RuntimeIdentifier` | **未设置** | 由命令行 `-r` 决定 |
| `PublishSingleFile` | **未设置** | 多文件发布 |
| `PublishReadyToRun` | **未设置** | |
| `InvariantGlobalization` | **未设置** | 需要 ICU/系统区域支持 |
| 原生库复制 | `None Include="..\..\Live2DCubismCore.dll"` + `CopyToOutputDirectory="PreserveNewest"`，且带 `Exists()` 条件 | 仓库根有该 DLL 才会拷到输出目录 |

`bin\Debug\net8.0-windows\` 实测：**31 个文件、7.9 MB**，其中
**没有 `coreclr.dll` / `hostfxr.dll` / `hostpolicy.dll` / 任何 `System.*.dll`**，
`AICompanion.runtimeconfig.json` 里声明：

```json
"frameworks": [
  { "name": "Microsoft.NETCore.App",       "version": "8.0.0" },
  { "name": "Microsoft.WindowsDesktop.App", "version": "8.0.0" }
]
```

→ 这是**框架依赖**构建，目标机必须自己装 .NET 8 桌面运行时。

同一目录里也**没有** `ai_asr.dll`、`libfvad.dll`、`llama-server.exe`、`ggml*.dll`：
它们靠 `bin\` 与 `modules\` 手工汇总，`dotnet publish` 不负责。

本机 `dotnet --list-runtimes` 有 `Microsoft.WindowsDesktop.App 8.0.31`，
所以**本机跑得起来完全不说明问题**——这正是"之前打包没带环境"的根源。

### 0.8 干净的框架依赖产物还差什么

把 `bin\Debug\net8.0-windows\` 直接拷到干净机器，除了程序集本身，还缺：

1. .NET 8 桌面运行时（`Microsoft.WindowsDesktop.App 8.0.x` + `Microsoft.NETCore.App 8.0.x`）
2. `ai_asr.dll` / `libfvad.dll`（要在 `bin\` 子目录，且默认配置就指向 `bin/ai_asr.dll`）
3. `llama-server.exe` + `ggml*.dll` + `llama*.dll` + `mtmd.dll`（在 `modules\llm-*\`）
4. `MSVCP140.dll` / `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll`
5. 模型（`models\llm\*.gguf` 等，按需）
6. `config.yaml`（首次启动会自动生成，但模板生成才不会带上开发机路径）

## 1. 两种分发形态

`tools/pack-release.ps1` 由 `-SelfContained` 决定出哪一种。

| | **自包含**（`-SelfContained $true`，默认） | **框架依赖**（`-SelfContained $false`） |
| --- | --- | --- |
| 包名 | `AICompanion-<版本>-<runtime>-selfcontained.zip` | `AICompanion-<版本>-<runtime>-framework.zip` |
| .NET 部分体积 | ≈ 155 MB（解压后） | ≈ 8 MB |
| 含 `modules\` 实测 | **282.6 MB 解压 / 114.4 MB zip / 349 文件** | **136.1 MB 解压 / 52.5 MB zip / 77 文件** |
| 目标机要求 | **不需要装任何 .NET**，解压即跑 | 必须先装 .NET 8 桌面运行时 |
| 缺少运行时的症状 | —— | 双击**无窗口、无日志、直接消失**（事件查看器里 .NET Runtime 报错） |
| 适用场景 | 给普通用户、群里发、离线交付、客服/直播机 | 内网批量部署、已有统一运行时的机器、CI 产物存档 |
| 主要风险 | 体积大；`.NET 8` 的生命周期跟着包走 | 用户没装运行时 → 最高频的"打不开"投诉 |

> 上面"≈155 MB / ≈8 MB"只是 .NET 部分的差额，也是"自包含 ≈150 MB、框架依赖 ≈10 MB"
> 这个说法的来源。但**两者实际都还要加 `modules\`（112 MB）**，
> 所以真实 zip 是 114 MB 与 52 MB，不是 150 MB 与 10 MB。
> 体积里 `models\` 默认不入包。

**建议**：面向最终用户一律出**自包含**包。框架依赖包的唯一优势是体积，
而"让用户先装 .NET"这一步在实际支持里会消耗掉省下的所有带宽。

## 2. 依赖清单

### 2.1 包内已包含（不需要目标机另外装）

| 依赖 | 位置 | 由谁带上 |
| --- | --- | --- |
| .NET 8 运行时 + WPF | 包根 `coreclr.dll`、`hostfxr.dll`、`System.*.dll`、`Microsoft.WindowsDesktop.App*` | `dotnet publish --self-contained true` |
| Live2D 渲染原生库 | `Live2DCubismCore.dll` | csproj 的 `None Include` + 脚本兜底 |
| ASR 原生库 | `bin\ai_asr.dll` | 脚本从仓库根 `bin\` 拷 |
| VAD 原生库 | `bin\libfvad.dll` | 同上 |
| LLM 后端 | `modules\llm-cuda\`、`modules\llm-vulkan\` | 脚本从 `modules\` 拷 |
| MSVC 运行库 | 包根 + 每个 `modules\llm-*\` 下的 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll` | 脚本从 `%SystemRoot%\System32\` 拷（app-local 部署） |

> MSVC 运行库为什么要放进**每个模块目录**：`llama-server.exe` 是独立子进程，
> 它的 DLL 搜索从自己所在目录开始，放包根它找不到。

### 2.2 目标机仍需提供

| 依赖 | 是否必需 | 说明 |
| --- | --- | --- |
| Windows 10/11 x64（或 ARM64） | 必需 | WPF + `net8.0-windows` |
| 显卡驱动 | 必需 | 有界面就要；GPU 推理更需要 |
| NVIDIA 驱动 | 用 `llm-cuda` 时必需 | 需要 `nvidia-smi` 与 CUDA 驱动 |
| CUDA 运行时 `cublas64_13.dll` | 用 `llm-cuda` 时必需 | **未随包**；装 CUDA 13.x 运行时，或改用 `llm-vulkan` |
| Vulkan 驱动（`vulkan-1.dll`） | 用 `llm-vulkan` 时必需 | 随显卡驱动安装；虚拟机/老驱动常缺 |
| .NET 8 桌面运行时 | 仅框架依赖包必需 | `Microsoft.WindowsDesktop.App 8.0.x` x64 |
| VC++ 2015-2022 x64 | 仅 `-NoVcRuntime` 时必需 | 正常包已 app-local 带上 |
| 模型文件 | 必需（否则无对话） | 见 §5 |

## 3. 怎么打包

### 3.1 一条命令

```bat
powershell -ExecutionPolicy Bypass -File tools\pack-release.ps1
```

默认 = `win-x64` + 自包含 + 含 `modules\` + 不含模型 → 给最终用户的包。

### 3.2 参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `-Runtime <win-x64\|win-arm64>` | `win-x64` | 目标架构 |
| `-SelfContained <bool>` | `$true` | 是否自带 .NET 8 运行时 |
| `-IncludeModel <bool>` | `$false` | 是否把 `models\` 打进包（1 GB 起） |
| `-IncludeModules <bool>` | `$true` | 是否把 `modules\` 打进包（关了就没有对话能力） |
| `-OutDir <路径>` | `<仓库>\dist` | 输出目录 |
| `-FrameworkOnly` | 关 | 等价 `-SelfContained:$false` |
| `-WithModel` | 关 | 等价 `-IncludeModel:$true` |
| `-NoModules` | 关 | 等价 `-IncludeModules:$false` |
| `-NoVcRuntime` | 关 | 不随包 MSVC 运行库 |
| `-NoSlim` | 关 | 不删 `.pdb`、不裁语言资源 |

> **给 cmd / `-File` 用户的坑**：`powershell -File` 传不了布尔值，
> `-SelfContained:$false` 会被当成字符串绑定失败。用 `pwsh -Command` 调用，
> 或者用上面的不带值开关。

常用组合：

```bat
:: 框架依赖、不含模型（约 55 MB zip）
powershell -ExecutionPolicy Bypass -File tools\pack-release.ps1 -FrameworkOnly

:: 自包含 + 模型（体积极大，仅在需要"解压即对话"时用）
powershell -ExecutionPolicy Bypass -File tools\pack-release.ps1 -WithModel
```

### 3.3 脚本干了什么

1. 从 `AICompanion.App.csproj` 的 `<Version>` 读版本号（包名可复现）；
2. 前置检查：`dotnet`、`Live2DCubismCore.dll`、`bin\ai_asr.dll`、`bin\libfvad.dll`、
   `modules\llm-*\module.json` + `llama-server.exe`，缺任何一项**直接中文报错退出**；
3. `dotnet publish -c Release -r <rid> --self-contained <bool> -p:PublishReadyToRun=false`，
   输出到 `artifacts\pack-release\<包名>\publish`（**不写 `src\...\bin\`**，
   所以程序开着也能打包）；
4. 汇总 `bin\`、`Live2DCubismCore.dll`、`modules\`、MSVC 运行库、`config.yaml`（模板）、
   `Assets\Default\`、`Knowledge\`、模型（按参数）；
5. 剔除 `.pdb`、多余语言目录、开发机运行期状态（`logs\`、`Assets\appearance.json`、
   `Knowledge\.pending`）；
6. 打 zip（条目名强制 `/`，符合 ZIP 规范）；
7. **校验**：逐条列出 zip 清单 + 总大小，并断言 §3.4 的必需项。

### 3.4 断言清单

缺任何一项 → 打印中文原因、`exit 1`、包标记为不可分发。

| 断言 | 条件 |
| --- | --- |
| `AICompanion.exe` | 总是 |
| `Live2DCubismCore.dll` | 总是 |
| `ai_asr.dll`（任意层级） | 总是 |
| `modules/llm-*/llama-server.exe` | `-IncludeModules $true` |
| `modules/llm-*/module.json` | `-IncludeModules $true` |
| `config.yaml` | 总是 |
| `coreclr.dll` | `-SelfContained $true` |
| `msvcp140.dll` | 未加 `-NoVcRuntime` |
| `libfvad.dll`、`hostfxr.dll`、`VERSION.txt` | 仅提示，不计失败 |

另外还有一条交叉校验：`-SelfContained` 声明与产物里**有没有 `coreclr.dll`** 必须一致，
不一致直接中止——避免"以为自包含其实不是"这种最贵的错。

### 3.5 与旧 `pack.ps1` 的分工

| | `pack-release.ps1` | `pack.ps1` |
| --- | --- | --- |
| 目的 | 可复现、可校验的发布 zip | 出一套完整安装包（含模型、CUDA 运行库、Inno Setup） |
| 模型 | 默认**不含** | 默认**含** |
| `modules\` | **含** | 不含（待修） |
| MSVC 运行库 | 含（app-local） | 不含 |
| 校验 | 内置断言 + `exit 1` | 交 `verify_dist.ps1` |
| 产物 | `dist\*.zip` | `dist\*` 目录 + `*-setup.exe` |

## 4. `config.yaml` 处理策略

**铁律：包里只给模板，永远不覆盖用户已有的配置。**

- 模板来源固定为 `src/AICompanion.Core/Configuration/config.default.yaml`
  （程序内嵌的出厂默认与它是同一份）。
- 脚本把模板复制成两个文件放进包根：
  - `config.yaml` —— 首次启动直接用的出厂配置；
  - `config.default.yaml` —— 供用户对照/恢复。
- **绝不会**把仓库根目录的 `config.yaml` 打进包。那份是本机个人配置，含
  模型绝对路径、参考音频路径、端口、音色选择，打出去等于公开开发机环境。
- 脚本内还有一道保险：目标位置若已存在 `config.yaml`（例如重复打包到非空目录），
  只提示、**不覆盖**。
- `pack.ps1` 旧行为同理，见其 4.3 节注释。

用户侧的约定：`config.yaml` 归用户所有，升级包只替换程序本体，不动它。
新增配置项由程序在读取时补默认值，不靠改文件。

## 5. 模块怎么分发

`modules\` 是"LLM 后端"的可插拔容器。程序扫描 `<程序目录>\modules\<name>\module.json`
来发现后端，用户可以自己增删目录来换后端。

```
modules\
├── llm-cuda\          # NVIDIA GPU
│   ├── module.json
│   ├── llama-server.exe
│   ├── ggml*.dll  llama*.dll  mtmd.dll
│   └── msvcp140.dll  vcruntime140*.dll      # 脚本随包，app-local
└── llm-vulkan\        # 通用 GPU（AMD / Intel / NVIDIA 都行）
    └── ... 同上
```

`module.json` 样例（`kind` 必须是 `llm`，`entry` 是可执行文件名）：

```json
{
  "name": "llm-vulkan",
  "kind": "llm",
  "display": "Vulkan 版对话模块",
  "requires": "vulkan",
  "entry": "llama-server.exe"
}
```

分发约定：

- **随包**：默认 `-IncludeModules $true` 把 `modules\` 下所有含 `module.json` 的目录整体带上
  （实测 CUDA 53.5 MB + Vulkan 58.5 MB）。
- **可增删**：用户直接删掉 `modules\llm-cuda\` 就退回 Vulkan；反之亦然。
  程序不会因为模块缺失而崩溃，而是在「设置 → 拓展模块」里提示"未发现模块"。
- **换后端**：删旧目录、放新目录、重启程序即可，不需要改 `config.yaml`。
- 验证单个包是否可用：

  ```bat
  powershell -ExecutionPolicy Bypass -File tools\verify_dist.ps1 -DistDir dist\AICompanion-<版本>-win-x64-selfcontained
  ```

- 已知外部依赖：`llm-cuda` 需要目标机的 `cublas64_13.dll`（CUDA 运行时）；
  `llm-vulkan` 需要显卡驱动提供的 `vulkan-1.dll`。想彻底免装 CUDA Toolkit，
  可在打包后手工把 `cublas64_13.dll`、`cublasLt64_13.dll`、`cudart64_13.dll`
  放进 `modules\llm-cuda\`（约 493 MB，`pack.ps1` 的老做法）。

## 6. 模型为什么不入包

一个 LLM 模型就 1 GB 起（本机 `models\llm\` 里最大的 `.gguf` 是 4.36 GB），
ASR 模型 141 MB。塞进 zip 的代价：

- zip 从约 110 MB 涨到 1.3 GB 以上，上传/下载/回归比对都不现实；
- 模型各自有独立授权（Qwen / DeepSeek 等），随包再分发需逐个确认；
- 用户往往已经有自己的模型，重复下载没有意义。

所以默认 `-IncludeModel $false`，包里只放 `models\README.txt` 说明放置位置：

```
models\
├── llm\*.gguf             对话模型（必需，否则只能看形象）
├── asr\ggml-base.bin     语音识别模型（可选，约 141 MB）
├── tts\*.wav             参考音频（可选，走 GPT-SoVITS / CosyVoice 时用）
└── piper\                Piper 音色（可选，本仓库不提供 piper.exe）
```

要点：

- 目录结构与仓库保持一致，程序按相对路径找。
- 放好后重启；启动日志会逐项写明"就位"还是"缺失降级"。
- 确实需要"解压即对话"时用 `-IncludeModel $true`，并接受 1.3 GB 级产物。
- **Piper 说明**：本仓库既没有 `piper.exe` 也没有 `models/piper/`，
  TTS 默认走 Windows SAPI，Piper 属可选增强。包里不承诺 Piper 可用。

## 7. 干净机器验收清单

"干净机器"指：没装 .NET SDK、没装 Visual Studio、没装 CUDA Toolkit、
没装 VC++ 可再发行包的 Windows 10/11。理想做法是全新虚拟机或 Windows 沙盒。

### 7.1 打包机侧（出包后立刻做）

- [ ] 脚本最后打印"打包成功"且**退出码 0**（`echo %ERRORLEVEL%`）；
- [ ] 断言表全部 `[通过]`，没有 `[缺失]`；
- [ ] zip 条目分隔符全是 `/`（脚本会打印"条目分隔符全为正斜杠"）；
- [ ] `unzip -l`（或 7-Zip）能看到 `modules/llm-cuda/llama-server.exe`；
- [ ] `git status` 里没有 `dist/`、没有 `*.zip`（`.gitignore` 已覆盖）。

### 7.2 目标机侧（解压后逐项）

1. **解压到普通用户可写目录**，例如 `%LOCALAPPDATA%\Programs\AICompanion`。
   **不要**放 `C:\Program Files\`——程序要在自己目录下写 `logs\` 与
   `Assets\appearance.json`，无写权限会失败。
2. 双击 `AICompanion.exe`，确认窗口出现（自包含包应**无任何前置安装**）。
3. 看 `logs\app\app-<日期>.log`，确认有"启动完成"，且没有 `[ERR]`。
4. 依赖检查（三选一，越靠前越硬）：
   - **Dependencies.exe**（lucasg/Dependencies，x64 版）打开
     `bin\ai_asr.dll`、`modules\llm-cuda\llama-server.exe`，
     确认 `MSVCP140.dll` / `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll` 全部
     解析到**包内路径**而不是"未找到"；
   - **`where` 兜底**（cmd）：
     `where /r . msvcp140.dll`、`where /r . vcruntime140.dll` 应能在包内找到；
   - **无工具兜底**：临时把 `C:\Windows\System32\msvcp140.dll` 改名（需管理员，
     谨慎）后启动，若仍正常说明 app-local 生效。
5. **dxdiag**（`Win+R` → `dxdiag`）：
   - 「显示」页确认有显示设备与驱动版本；
   - 若要 GPU 推理，确认驱动日期/版本不是古董；
   - Vulkan 后端可在「系统」页/驱动面板确认 Vulkan 支持，或用
     `vulkaninfo`（Vulkan SDK 自带）确认 `vulkan-1.dll` 可用。
6. **NVIDIA 用户**：`nvidia-smi` 能跑通，说明驱动在；
   `llm-cuda` 还额外需要 `cublas64_13.dll`（见 §5）。
7. 首次启动后关闭再开，确认第二次没有重复建目录报错（幂等）。
8. 卸载/删除目录后不留残留（除了 `%LOCALAPPDATA%\AICompanion` 里的日志）。

### 7.3 常见启动失败排查

| 症状 | 最可能原因 | 处理 |
| --- | --- | --- |
| 双击**毫无反应**，无窗口无日志 | 框架依赖包 + 目标机没装 .NET 8 桌面运行时 | 换自包含包，或装 `Microsoft.WindowsDesktop.App 8.0.x` x64。查事件查看器 → Windows 日志 → 应用程序，找 `.NET Runtime` 错误 |
| 窗口出现，但**没有形象**（纯色块） | 缺 `Live2DCubismCore.dll` 或模型路径不对 | 确认包根有该 DLL；`config.yaml` 的 `live2d.default_model_path` 指向 model3.json |
| 窗口出现，**对话不可用** | 缺 `modules\`、缺 `llama-server.exe`、缺模型、或 MSVC 运行库缺失 | 看日志里"模块"与"模型"两行；用 Dependencies 查 `llama-server.exe` 的 `VCRUNTIME140.dll` |
| 「未发现模块」 | `modules\` 里没有含 `module.json` 的目录 | 按 §5 放目录；确认 `module.json` 的 `kind` 是 `llm` |
| `llama-server.exe` 启动即退出 | `llm-cuda` 缺 `cublas64_13.dll` | 装 CUDA 13.x 运行时，或删掉 `modules\llm-cuda\` 用 Vulkan |
| 连不上 LLM / 一直重连 | 端口被占，或后端崩溃 | 查 `logs\chat\`；换 `llm-vulkan`；确认 `config.yaml` 的端口未被占用 |
| 语音识别不可用 | 缺 `bin\ai_asr.dll`、缺 `models\asr\ggml-base.bin`、MSVC 运行库缺失 | 逐项对照日志 |
| 日志里 `LogRoot` 相关报错 | 程序目录不可写 | 移出 `Program Files`，或改 `LogRoot` 到可写路径 |
| 中文乱码 | 控制台代码页 / 字体 | 与本打包流程无关；脚本本身要求存成 **UTF-8 带 BOM** |
